# 매칭 구조: 다중 요청 방식

- 작성일: 2026-11-03
- 출발점: Rover를 직접 써보며 느낀 불편함

## 1. 문제: Rover 검색의 한계

- 위치, 강아지 크기, 날짜로 검색해도 결과가 거리순이나 가격순으로 정렬되지 않음. 기준이 불투명한 자체 순위로 노출됨.
- 가까운 시터라도 리뷰가 적거나 없으면 아래로 밀리고, 멀어도 리뷰가 많으면 위에 뜸.
- 그래서 새로 들어온 시터는 가격을 최저로 내려야만 첫 고객을 모을 수 있음.
- 급하게 시터를 구할 때 보호자가 여러 명에게 같은 메시지를 일일이 복사해서 보내야 함.

## 2. 제안: 걸러진 후보 + 다중 요청

1. 보호자가 조건(위치, 강아지 크기, 날짜·시간)을 입력하면, 시스템이 조건에 맞는 시터 **5~10명만** 추려서 보여줌.
2. 보호자가 체크박스로 원하는 시터를 골라 **한 번에 요청**을 보냄.
3. **먼저 수락한 시터**와 대화가 시작되고, 조건이 맞으면 예약 확정. 나머지 시터의 요청은 자동으로 닫힘.

### 보조 규칙

- **보험은 앱 안에서 예약한 건만 보장함.** 앱 밖에서 직접 거래하면 보험 적용을 받을 수 없으므로, 이것이 직거래를 막는 핵심 장치가 됨.
- **가격은 시터가 직접 정함.**
- **내 시터 저장:** 마음에 든 시터를 저장하면, 조건이 맞을 때 검색 결과에 항상 포함됨.
- **신규 시터 노출 보장:** 검색 결과에 새로 들어온 시터를 최소 2명 포함함.

## 3. 기대 효과

1. **앱 밖 직거래 방지:** 앱 안에서 예약한 건만 보험으로 보장됨(핵심 장치). 여기에 더해 시터의 가능 시간과 조건에 따라 결과가 바뀌므로, 한 시터와만 계속 거래하는 구조가 덜 고착됨.
2. **신규 시터 정착:** 가격을 내리지 않아도 노출될 기회가 생김.
3. **급할 때 편리함:** 요청이 여러 시터에게 자동으로 전달되므로 복사·붙여넣기가 필요 없음.

---

## 4. 검토 메모 (Claude)

**좋은 점**
- 급하게 구할 때 여러 명에게 한 번에 보내는 기능은 Rover에 없는 확실한 차별점.
- 신규 시터 노출을 보장하면 공급이 빨리 자리 잡음. 출시 초반에 특히 중요함.

**정리가 필요한 점**

1. **직거래 방지 논리와 "내 시터 저장"이 서로 부딪침.** 반려견 보호자는 보통 같은 시터를 계속 쓰고 싶어함(개가 익숙해지기 때문). 저장 기능이 이를 허용하니, 검색 결과가 바뀐다는 것만으로는 직거래가 크게 줄지 않음. 직거래가 생기는 진짜 이유는 수수료이므로, "앱 안에서 다시 예약하는 게 가장 편하고 안전하다"(저장한 시터 재예약 1탭, 보험은 앱 결제 시에만 적용 등)는 방향이 더 확실함. 로컬에서 검토 중인 직거래 방지안과 함께 맞춰보면 좋음.
2. **시터 입장의 피로도.** 요청을 받고 수락했는데 다른 시터가 먼저 잡으면 헛수고가 됨. 이런 일이 반복되면 시터가 요청에 반응하지 않게 될 수 있음. 보완안 예시:
   - 요청을 받을 때 "다른 시터 N명에게도 함께 보낸 요청"이라고 표시
   - 자동으로 1등을 확정하지 않고, 짧은 시간(예: 10분) 동안 수락한 시터 중에서 보호자가 고르게 함
   - 시터의 수락률이 낮아지지 않도록, 놓친 요청은 시터 지표에 반영하지 않음
3. **"먼저 매칭"의 정의.** 먼저 수락한 시터와 대화했는데 조건이 안 맞으면, 다음 수락자에게 넘어갈 수 있는지 정해야 함. 수락한 시터들을 대기열로 두는 구조를 추천.
4. **후보 선정 기준을 공개.** Rover의 불편함이 "기준이 불투명하다"는 점이었으므로, 5~10명을 고르는 기준(거리, 가능 시간, 크기 조건, 가격대)을 보호자에게 보여주는 게 일관됨. 거리순·가격순 정렬도 선택할 수 있게 하는 걸 추천.
5. **신규 시터 품질.** 노출을 보장하는 만큼, 신규 시터는 인증과 퀴즈를 완료해야 노출 대상이 되게 하는 걸 추천.
