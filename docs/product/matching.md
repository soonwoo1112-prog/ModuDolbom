# 매칭 구조: 다중 요청 방식

- 작성일: 2026-11-03
- 출발점: Rover를 직접 써보며 느낀 불편함

## 1. 문제: Rover 검색의 한계

- 위치, 강아지 크기, 날짜로 검색해도 결과가 거리순이나 가격순으로 정렬되지 않음. 기준이 불투명한 자체 순위로 노출됨.
- 가까운 시터라도 리뷰가 적거나 없으면 아래로 밀리고, 멀어도 리뷰가 많으면 위에 뜸.
- 그래서 새로 들어온 시터는 가격을 최저로 내려야만 첫 고객을 모을 수 있음.
- 급하게 시터를 구할 때 보호자가 여러 명에게 같은 메시지를 일일이 복사해서 보내야 함.

## 2. 제안: 걸러진 후보 + 다중 요청

### 예약 흐름

1. 보호자가 조건(위치, 강아지 크기, 날짜·시간)을 입력함.
2. 시스템이 조건에 가장 잘 맞는 시터를 **3~10명** 추려서 보여줌. 기본 인원 수는 테스트로 정함.
3. 보호자가 체크박스로 원하는 시터를 골라 **한 번에 요청**을 보냄.
4. 요청을 받은 시터는 **대화창 열기** 또는 **거절**을 선택함. 시터가 바로 예약을 확정하는 방식이 아님.
5. 보호자와 시터가 짧게 대화한 뒤, 조건이 맞으면 예약을 확정함. 확정되면 나머지 요청은 자동으로 닫힘.

### 후보 선정 기준

- **거리, 리뷰, 가격을 종합**해서 가장 잘 맞는 시터를 띄움.
- 한 가지 기준으로만 정렬하지 않는 이유: 그렇게 하면 애매한 위치에 사는 시터는 거의 노출되지 않음.
- 그래서 결과에 서로 다른 강점을 가진 시터가 섞이게 함. 예시:
  - 리뷰가 많고 가격이 높은 유명 시터
  - 100m 이내의 아주 가까운 시터
  - 새로 들어온 시터 (1~2명 보장)
  - 보호자가 지정한 전담시터

### 보조 규칙

- **보험은 앱 안에서 예약한 건만 보장함.** 앱 밖에서 직접 거래하면 보험 적용을 받을 수 없으므로, 이것이 직거래를 막는 핵심 장치가 됨.
- **가격은 시터가 직접 정함.**
- **전담시터(가칭):** 한 번 예약한 시터를 전담시터로 지정하면, 이후 검색 결과에 항상 포함됨.
- **신규 시터 노출 보장:** 검색 결과에 새로 들어온 시터를 1~2명 항상 포함함.
- **급한 예약:** 후보 범위를 넓히고, 평균 답장 시간이 빠르고 수락률이 높은 시터를 우선 포함함.
- **검색 결과 표시 정보:** 사진, 이름, 한 줄 소개, 가격, 직선거리, 리뷰 수, 재이용 고객 수, 평균 답장 시간, 같은 아파트 태그.
- **같은 아파트 태그:** 보호자와 같은 아파트(단지)에 사는 시터에게 "같은 아파트" 태그를 붙임. 거리순으로 정렬할 때도 표시함.

### 시터 분석 페이지

시터가 자기 성과를 확인할 수 있는 페이지. 표시 항목 예시:

- 검색 결과에 노출된 횟수
- 프로필 조회 수
- 받은 요청 수, 대화로 이어진 수, 확정된 수

## 3. 기대 효과

1. **앱 밖 직거래 방지:** 앱 안에서 예약한 건만 보험으로 보장됨(핵심 장치). 여기에 더해 시터의 가능 시간과 조건에 따라 결과가 바뀌므로, 한 시터와만 계속 거래하는 구조가 덜 고착됨.
2. **신규 시터 정착:** 가격을 내리지 않아도 노출될 기회가 생김.
3. **급할 때 편리함:** 요청이 여러 시터에게 자동으로 전달되므로 복사·붙여넣기가 필요 없음.
4. **시터의 자기 관리:** 분석 페이지를 보고 가격이나 프로필을 스스로 조정할 수 있음.

## 4. 검토 메모 (Claude)

**반영 완료**
- 시터가 대화창 열기 또는 거절을 고르는 방식으로 바꿔서, 시터가 먼저 확정해야 하는 경쟁과 헛수고 문제가 줄어듦.
- 종합 기준과 강점별 후보 섞기로, 순위 기준이 불투명하다는 문제와 일부 시터가 노출되지 않는 문제를 함께 해결함.

**남은 확인 사항**
1. **선정 기준을 보호자에게 보여주기.** 각 후보에 "가장 가까움", "리뷰 많음", "신규", "같은 아파트" 같은 이유 태그를 붙이면, Rover와 달리 왜 이 시터가 떴는지 투명하게 알 수 있음.
2. **대화가 길어지는 문제.** 여러 시터와 동시에 대화가 열릴 수 있으니, 요청에 응답 마감 시간(예: 30분, 급한 예약은 더 짧게)을 두는 걸 추천. 확정 뒤 닫힌 시터에게는 "다른 시터로 확정됨"이라는 알림을 보내야 함.
3. **같은 아파트 태그와 개인정보.** 시터의 거주지가 드러나는 기능이므로 시터가 직접 켜는 방식(동의)으로 하고, 단지명까지만 보여주고 동·호수는 보여주지 않아야 함. 거주지 인증과 연결하면 태그가 정확해짐.
4. **분석 페이지 확장.** 같은 동네 시터들의 평균 가격이나, 노출 대비 요청 비율(전환율)까지 보여주면 시터가 가격을 정할 때 도움이 됨.
5. **3명이면 충분한지.** 급한 예약에서는 3명 모두 거절할 수 있음. 급한 예약일 때는 더 많이 띄우거나, 모두 거절되면 다음 후보를 자동으로 추천하는 기능을 추천.
