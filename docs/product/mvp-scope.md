# 첫 출시(v1) 범위와 기술 과제

- 작성일: 2026-11-11
- 정리한 곳: 기획 대화(폰 세션). 디자인 세션의 캔버스(`design/canvas/canvas.json`)와 함께 본다.

## 1. 기본 방향

- **경쟁 서비스가 이미 있는 시장이다.** 그래서 첫 버전부터 최종 앱만큼 완성도 있게 만든다. 모두돌봄이 주는 느낌, 즉 UX가 가장 중요한 경쟁력이다.
- **구현이 쉬운 기능은 v1에 모두 넣는다.** 화면과 데이터만 있으면 되는 기능이 여기에 해당한다.
- **기술이나 제휴 때문에 어려운 기능만 뒤로 미룬다.** 대신 버튼과 자리는 화면에 미리 두고, 누르면 "준비 중" 안내를 보여 준다. ([5절](#5-준비-중-기능을-보여-주는-방법))

## 2. 기능 범위

### v1에 넣는 기능

| 영역 | 기능 |
|---|---|
| 예약 | 조건 입력, 추천 시터 3~10명, 여러 명에게 한 번에 요청, 요청 현황, 확정되면 나머지 요청 자동 회수, 급한 예약 |
| 시터 노출 | 거리·리뷰·가격 종합 추천, 신규 시터 1~2명 노출 보장, 같은 아파트 태그, 전담 시터 |
| 채팅 | 요청으로 열리는 채팅, 예약 수정 요청, 예약 정보, 채팅 목록 분류 |
| 산책 | 산책 시작·종료, **실시간 위치 보기**, 산책 소식(사진, 배변), 산책 기록, 후기 |
| 소셜 | 산책 로그·사진 피드, 동네 커뮤니티, 좋아요·댓글, 게시글에서 시터 프로필로 이동해 예약. **커뮤니티는 핵심 차별점이라 반드시 v1에 넣는다.** |
| 캘린더 | 보호자 캘린더, 시터 캘린더와 가능한 날짜·시간 설정 |
| 프로필 | 강아지 프로필, 시터 프로필(가격, 소개, 산책 기록), 보호자 프로필 |
| 시터 | 서비스 설정, 시터 분석, 정산 내역 |
| 계정 | 로그인·회원가입, 본인·계좌·거주지 인증, 시팅 팁 퀴즈 |
| 결제 | 앱 결제, 시터 정산 |
| 알림 | 푸시 알림, 알림 목록 |

## 3. 놓치기 쉬운 기능과 화면

화면을 그릴 때 자주 빠지지만, 실제 서비스에는 꼭 필요한 것들.

- **푸시 알림:** 여러 시터에게 동시에 요청하는 구조는 알림 없이는 작동하지 않는다. 새 요청, 대화 시작, 확정, 산책 시작·종료, 산책 기록 도착 때 알린다.
- **취소·환불·노쇼:** 누가, 언제까지 취소하면 얼마를 돌려받는지에 대한 정책과 화면. 시터가 오지 않았을 때와 보호자가 연락이 안 될 때의 처리.
- **신고·차단:** 채팅과 프로필, 게시글에서 신고하고 차단하는 기능.
- **운영자 관리 화면:** 시터 가입 승인, 신고·분쟁 처리, 환불 처리. 앱 화면은 아니고 운영팀이 쓰는 내부 화면이다. 처음엔 아주 단순해도 된다.
- **고객센터:** v1은 카카오톡 채널 연결.
- **상태 화면:** 흐름마다 "기다리는 중 / 아무도 수락하지 않음 / 취소됨 / 오류 / 내용 없음" 화면.
- **권한 요청:** 위치(특히 시터의 백그라운드 위치), 알림, 사진 권한을 왜 필요한지 설명하고 요청하는 화면.

### 캔버스에 아직 없는 화면

2026-11-11 캔버스 기준.

- 로그인, 회원가입, 보호자·시터 역할 선택
- 본인 인증, 계좌 인증, 거주지 인증, 시터 가입 퀴즈, 가입 심사 대기
- 결제 화면, 결제 수단 관리, 보호자 결제 내역
- 취소·환불 화면, 노쇼 신고
- 신고·차단
- 설정, 고객센터 연결
- 위치·알림·사진 권한 요청
- 아무도 수락하지 않았을 때의 요청 현황
- "준비 중" 안내 시트

## 4. 핵심 기술 과제

화면보다 구현이 막막한 부분들. 각각 무엇이 필요하고, 어떻게 풀지 정리했다.

### 4-1. 앱 스택 (가장 먼저 정할 것)

**추천: React Native(Expo) + Supabase**

- **React Native(Expo):** 코드 하나로 iOS와 Android 앱을 함께 만든다. 지금 미리보기(`app-preview/`)가 JavaScript라서 옮겨 가기도 쉽다.
- **Supabase:** 로그인, 데이터베이스, 실시간 기능(채팅, 위치 공유), 사진 저장을 한곳에서 제공한다. 처음에 서버를 따로 만들 필요가 적다.

### 4-2. 로그인·회원가입

- **소셜 로그인:** 카카오, 네이버, Apple. iOS 앱에서 카카오 같은 소셜 로그인을 제공하면 Apple 로그인도 함께 넣어야 한다(App Store 심사 규정).
- **구현:** Supabase Auth가 카카오와 Apple 로그인을 지원한다. 네이버는 추가 작업이 필요할 수 있으니 확인한다.

### 4-3. 본인·계좌·거주지 인증

- **본인 인증(휴대폰):** PASS 같은 휴대폰 본인 인증은 직접 만들 수 없다. 포트원 같은 인증 대행 서비스와 계약해서 붙인다. **사업자등록이 먼저 필요하다.**
- **계좌 인증:** 시터 정산 계좌가 본인 명의인지 확인한다. 보통 "1원 송금 인증" 서비스를 쓴다. 정산을 맡는 결제 대행사(PG)가 함께 제공하는지 확인한다.
- **거주지 인증:**
  - 동네 인증: 휴대폰 GPS로 그 동네에 있는지 확인한다(당근마켓 방식). 구현이 비교적 쉽다.
  - 같은 아파트 인증: 주소 검색 API(카카오 또는 행정안전부 도로명주소)로 받은 건물 정보로 같은 단지인지 판단한다. 실제 거주 확인이 더 필요하면, 처음엔 서류 사진을 받아 운영팀이 직접 확인하는 방법도 있다.

### 4-4. 결제와 정산

- **구조:** 보호자가 확정할 때 결제 → 산책이 끝나면 수수료를 뺀 금액을 시터에게 정산.
- **결제 대행사(PG):** 토스페이먼츠, 포트원 등. 산책처럼 앱 밖에서 제공되는 서비스는 Apple·Google 인앱결제를 쓰지 않아도 되므로, 일반 카드 결제를 붙일 수 있다.
- **정산:** 여러 시터에게 돈을 나눠 보내야 하므로, PG사의 "지급 대행"이나 "에스크로" 상품이 필요하다. 회사가 직접 돈을 받아 나눠 주는 방식은 규제 문제가 생길 수 있다.
- **사전 준비:** 사업자등록, 통신판매중개업 신고가 필요하고, PG 심사에 몇 주가 걸린다. 일찍 시작해야 한다.
- **세금:** 프리랜서 시터에게 지급할 때 원천징수(3.3%) 처리 여부를 세무사에게 확인한다.

### 4-5. 실시간 위치(GPS) 추적

가장 어려운 과제다.

- **구조:** 시터 휴대폰이 산책 중 위치를 몇 초마다 서버로 보낸다 → 보호자 앱이 실시간으로 받아 지도에 그린다 → 산책이 끝나면 경로를 산책 기록에 저장한다.
- **어려운 점:**
  - 화면이 꺼져도 위치를 계속 기록해야 한다(백그라운드 위치). iOS와 Android 모두 권한이 까다롭고, 앱 심사에서 이유를 설명해야 한다.
  - 배터리 소모, GPS 튀는 값 보정.
- **구현:** Expo의 위치 기능(백그라운드 작업) 또는 전문 위치 라이브러리 + Supabase 실시간 기능. 지도는 카카오맵이나 네이버 지도 SDK.
- **법적 준비:** 다른 사람의 위치 정보를 다루는 서비스는 **위치기반서비스사업자 신고**(방송통신위원회)가 필요하다. 개인위치정보 이용 동의 화면도 넣어야 한다.

### 4-6. 채팅

- Supabase 실시간 기능으로 직접 만들 수 있다.
- 더 빨리 만들려면 Sendbird 같은 채팅 전문 서비스를 쓸 수 있지만, 사용자가 늘면 비용이 커진다.

### 4-7. 푸시 알림

- Expo의 알림 기능으로 iOS(APNs)와 Android(FCM)를 함께 처리한다. 구현은 어렵지 않다.

### 4-8. 사진

- Supabase 저장소에 올린다. 올리기 전에 크기를 줄여서 비용과 속도를 관리한다.

### 미리 시작해야 하는 행정 절차

기간이 걸리는 일이라 개발과 동시에 시작한다. 정확한 요건은 행정사나 세무사에게 확인한다.

1. 사업자등록
2. 통신판매중개업 신고
3. 위치기반서비스사업자 신고
4. PG 계약, 본인 인증 서비스 계약

## 5. "준비 중" 기능을 보여 주는 방법

버튼과 자리는 최종 앱처럼 두되, 아래 규칙을 지킨다.

- **누르면 바텀 시트로 안내한다.** 예: "곧 만나요. 준비되면 알려 드릴게요." 그리고 "알림 받기" 버튼을 둔다. 막다른 화면으로 보내지 않는다.
- **핵심 흐름에는 두지 않는다.** 예약, 채팅, 산책, 결제 흐름 중간에 "준비 중"이 나오면 앱이 미완성으로 느껴진다.
- **개수를 적게 유지한다.** "준비 중"이 많으면 오히려 완성도가 떨어져 보인다. 보험, AI 경로처럼 꼭 미뤄야 하는 것만 남긴다.
- **고객센터처럼 다른 수단으로 대신할 수 있으면, 대신한다.** 예: 카카오톡 채널로 연결.
